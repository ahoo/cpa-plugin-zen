# Offline exact-Host integration gate

This gate tests **protocol behavior only**. It never calls real Zen or tests provider identity, geographic gates, quotas, or production availability. Do **not** run `scripts/e2e/run.sh` or `scripts/mint_sessions.py` for this gate; those use live upstreams.

From the plugin source directory, run `scripts/offline-e2e/run.sh --build`. This builds a glibc c-shared plugin with cached Go 1.26 dependencies (`GOPROXY=off`) into temporary staging; it does not invoke `build.sh`, `go mod tidy`, or write to production plugin discovery. Alternatively use `scripts/offline-e2e/run.sh --plugin /absolute/path/to/temporary/staged/zen.so`; production discovery and source-tree artifacts are rejected. Requires Docker, bash, a local Go 1.26 toolchain for `--build`, the cached Python 3.12 Alpine image, and the **unchanged** Host image exactly `sha256:793691b3817afff2679999bfd173f23e63b0cc05517859f78d8adcc5c5345ea1` (CLIProxyAPI v7.3.13). Missing images fail closed; the script does not pull images.

The runner creates a Docker `--internal` network and three temporary containers: Python stdlib mock upstream, pinned Host, and Python stdlib assertion client. The Host uses a generated config, synthetic API keys/session pool, and `paid.base_url: http://mock:9999` (used by both paid and free routes). No production config, auth, plugin directory, Docker socket or host port is mounted; proxy environment variables are cleared. All three containers remain on the internal network, and every upstream model/endpoint is allowlisted by the mock. Containers, network, and staged files are removed on exit, including failures. No production service restart occurs.

The gate covers `/v1/chat/completions`, `/v1/responses`, and `/v1/messages` in stream and non-stream modes: synthetic paid SystemOne and free chat/Responses mapping, text and tools, usage, Responses delta+done/done-only behavior, single SSE terminal and no double `data:` framing, deterministic and event errors, and one paid fallback after a synthetic 503. A one-second synthetic cooldown is allowed to expire between fallback and deterministic-error cases; this does not change scheduling policy. Host/ABI cancellation boundaries and real-network behavior remain outside this protocol gate.
